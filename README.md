# Delivery ETA Predictor

> Предсказание времени доставки еды с помощью градиентного бустинга (CatBoost + Optuna).
---

## О проекте

**Delivery ETA Predictor** — это end-to-end ML-проект для предсказания **времени доставки заказа** (в минутах) на основе данных о заказе, клиенте, курьере, ресторане и погодных условиях.

Проект решает задачу **регрессии** и демонстрирует полный цикл разработки ML-продукта: от анализа данных и feature engineering до обучения модели и её интеграции в сервис предсказаний.

**Стек:** Python · CatBoost · Optuna · scikit-learn · pandas · Pydantic · FastAPI

---

## Бизнес-задача

В сфере доставки еды точное предсказание времени доставки — **критически важный фактор**:

| Стейкхолдер | Проблема | Ценность решения |
|-------------|----------|------------------|
| **Клиенты** | Неточные оценки → недовольство, отмены | Точный ETA → доверие, повторные заказы |
| **Рестораны** | Сложно планировать загрузку кухни | Прогноз → оптимизация процессов |
| **Курьеры** | Неоптимальное распределение заказов | Эффективная загрузка → больше заказов |
| **Бизнес** | Потери на компенсациях и поддержке | Снижение издержек, рост NPS |

**Цель:** построить модель с **MAE < X.X минут**, что позволит давать клиентам точный ETA, оптимизировать логистику и снижать операционные издержки.

---

##  Техническая задача

- **Тип задачи:** регрессия
- **Целевая переменная:** `delivery_time_minutes` (непрерывная, в минутах)
- **Метрики:** MAE (основная), MSE, R²
- **Объём данных:** ~300 000 заказов
- **Количество признаков:** 26

**Почему MAE?**
- Интерпретируется в **минутах** — понятно бизнесу
- Устойчива к выбросам (в отличие от MSE)
- Прямо отражает «среднюю ошибку в минутах»

## Методология

### 1. Разбиение данных

Используется **разбиение по времени**, а не случайное — это критично для временных рядов и предотвращает **утечку данных (data leakage)**.

| Выборка | Доля | Период |
|---------|------|--------|
| Train | 60% | Ранние заказы |
| Validation | 20% | Средние заказы |
| Test | 20% | Поздние заказы |

### 2. Оптимизация гиперпараметров

Через **Optuna** (TPE sampler) подбираются 8 параметров:

| Параметр | Диапазон | Log-шкала |
|----------|----------|-----------|
| `iterations` | 500–1500 | Нет |
| `learning_rate` | 0.01–0.2 | Да |
| `depth` | 4–10 | Нет |
| `l2_leaf_reg` | 1–10 | Да |
| `border_count` | 32–255 | Нет |
| `bagging_temperature` | 0–1 | Нет |
| `random_strength` | 1–10 | Нет |
| `min_data_in_leaf` | 1–30 | Нет |

**Целевая метрика:** MAE на валидации
**Количество trials:** 30–50

### 3. Обучение

- **Early stopping:** 75 раундов
- **`use_best_model=True`** — берётся лучшая итерация
- **Финальная оценка** на test set

### 4. Инференс

- Валидация входных данных через **Pydantic**
- Проверка **порядка колонок** через `model.feature_names_`
- Поддержка **категориальных признаков** через `Pool`
